Registry anchor

The CP Registry’s anchor key

The Registry periodically signs the head of its audit chain. This page carries the public key that signature is made with, so that anyone can check an anchor without taking the Registry’s word for anything.

Why this page exists

Every act on the Connection Profile Registry is written to an append-only log, each entry carrying a hash of the one before it. That makes editing the past detectable: change anything and every entry after it stops matching.

What hashes alone cannot catch is a fork — a registry keeping two internally consistent histories and serving one to each party. Both would verify. Neither party could tell. So the operator signs the head of the chain with a key held outside the Registry’s own infrastructure, and publishes the result. Two parties whose copies match the same signed head are provably holding the same history.

That only works if you can confirm which key is the real one — and a key announced only by the Registry proves nothing about the Registry. Hence this page, and the fingerprint below, to be compared by eye.

The root key

In use since 14 September 2026. Vouched for by nothing else — that is what makes it the root.

Key id

cp-anchor-2026-09

Public key (base64url, Ed25519)

Rj9bGQe5TSJWmlcQoa4lJer0oj4r9lL6TJQQrqhDynI

Fingerprint (the raw key bytes, in hex — the same 32 bytes as above, written so a person can compare them)

463f 5b19 07b9 4d22 569a 5710 a1ae 2525 eaf4 a23e 2bf6 52fa 4c94 10ae a843 ca72

If an anchor names a key whose fingerprint is not this one, and which is not vouched for by a chain of signatures leading back to this one, it is not this Registry’s anchor — whatever it claims about its origin.

Checking it yourself

No account, no credential, no relationship with the operator.

The current anchor is served at cp.cnscp.io/.well-known/cp-anchor, and the keys it may be signed by at /.well-known/cp-keys. The Registry’s own tooling will walk the public journal and compare it against the signed head:

npm run verify-journal -- https://cp.cnscp.io --anchor cp-anchor-2026-09

The same anchors are mirrored in a public repository the Registry does not control, so the two copies can be compared. A disagreement between them is not an inconvenience — it is the evidence.

The mechanism, the cadence and its limits are described in full in the Registry’s design document, §20.2.
